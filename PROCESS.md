### Evaluation Harness
- **eval/correctness.py** — 5-stage gate (smoke → shape-sweep → numerical stability → determinism → anti-cheat) with short-circuit failure attribution. Injectable `ComparisonPolicy` (torch-free at import); `TorchComparisonPolicy` delegates to `sol_execbench.compute_error_stats` and fails closed without SOL. Workload-carried `ToleranceSpec` overrides every stage's atol/rtol — including stage 5's strict tolerances — so anti-cheat matches the per-problem spec (opt-in via `workload` presence).
- **eval/inputs.py** — `build_reference_fn` (exec PyTorch reference, resolve `run`) + `build_input_generator` (wraps SOL's `gen_inputs` with seeding) + `allocate_dps_outputs` (Tier 6). - **eval/benchmark.py** — CUDA-event timing via injectable `BenchmarkTimer` Protocol. Production `_TorchCudaTimer` uses `torch.cuda.Event` pairs + 256MB int64 L2 thrasher. Multi-workload parallel-list contract with fresh-timer-per-workload isolation; fail-closed on partial-workload failures (<half survive → `BenchmarkError`); 100us sentinel on empty-workload path; `is_fully_successful` for orchestrator gating. A1 PR 1/B: one autotune burn-in call fires before warmup at reserved seed `_BURN_IN_SEED = -1` so Triton's autotune compile + config sweep stays outside the timed window. `benchmark_kernel(..., autotuner=...)` snapshots `autotuner.cache` around each workload and records `BenchmarkResult.autotune_winner_per_workload` from single-entry cache deltas. `benchmark_kernel` clears `autotuner.cache` at entry to keep per-workload cache-delta winner attribution correct after the Coder's correctness pass (the correctness pass compiles + launches the kernel before bench, so Triton's `@triton.autotune` may have already cached winners for our workload shapes); flips `autotuner_usable=False` defensively on `AttributeError`.
- **eval/profiler.py** — hybrid analytical roofline (optional, degrades to NCU-only on missing byte counts) + curated NCU subprocess (best-effort, degrades on failure). Curated NCU subset = REQUIRED {`sm_occupancy_pct`, `l2_hit_rate_pct`} + OPTIONAL {`tensor_core_util_pct: float | None`}; absence of an OPTIONAL metric yields None rather than degrading the whole profile (e.g. Ada elementwise kernels emit no tensor-core counter; discarding occupancy + L2 + stalls because one diagnostic is missing was a regression of the "degrade gracefully" contract). `ProfilingResult.analytical: AnalyticalMetrics | None` with `has_analytical` property; `profile_kernel(nbytes=0)` skips the analytical block, NCU still runs. Source-hash-keyed cache stores both the curated `NCUMetrics` and the full `raw_metrics` dict; cache hits rehydrate both so `Reviewer.query_metric` works the same on re-profile as on the originating iteration. Per-iter signals feed Reviewer; run-level classification via `classify_run`.
- **eval/roofline.py** — two clean paths: SOLAR (`derive_t_sol_from_solar`, `source="solar"`) or built-in `compute_roofline()` fallback (`source="builtin"`). `RooflineResult.bottleneck` typed as `BottleneckType` enum end-to-end. `RooflineResult.total_flops` / `total_fused_bytes` carry SOLAR's absolute counts through to downstream consumers.
- **benchmark/roofline_shapes.py** — `compute_roofline_inputs(definition, workload, *, roofline=None)` accepts an optional `RooflineResult`; when SOLAR-derived `total_flops` / `total_fused_bytes` are both > 0 they outrank the shape formulas, and the function returns `(0, nbytes)` when only flops can't be derived (view/mask-heavy kernels) so analytical degrades cleanly to memory-only or NCU-only rather than failing closed.
- **eval/scorer.py** — SOL Score formula + `reward_hack_suspect` / `calibration_warning` audit flags (SOL-ExecBench paper §4.3).
- **eval/anti_cheat.py** — three surfaces: correctness-level (Stage 5 in `eval/correctness.py`), performance-level (scorer audit flags), process-level (`per_iter_anti_cheat` context manager + `check_lazy_outputs_after_bench` wired to SOL's `reward_hack` detector set). Active clock-lock end-to-end on RTX 6000 Ada.

### Actions & Memory
- **actions/registry.py** + **tier1-6** — `Action` dataclass, `ActionTier` enum, `build_default_registry()`. `guidance` / `anti_patterns` / `expected_impact` text synthesized from the 9-paper KB + AccelOpt / Astra / autokernel / cuda-optimized-skill / evotoolkit catalogs. `Action.min_compute_capability: float | None` is the typed enforcement field; `list_applicable(kernel_type, *, hardware=None)` filters by kernel_type + hardware (deny-on-None for unknown HW) via `_hardware_meets`. `Action.preconditions: list[str]` is now LLM-visible documentation only (rendered into the Planner's system prompt — no structured filter consumes it). Tier-5 actions populate `min_compute_capability`: `t5_h100_tma` / `t5_h100_wgmma` / `t5_hopper_cluster` = 9.0; `t5_a100_cp_async` = 8.0.
- **memory/{experience,store,retriever,summarizer,producer}.py** — Distilled-lesson optimization memory (AccelOpt-style). `Experience` carries `(row_id, schema_version, kernel_type, hardware_arch, scope, speedup, action_applied, title, lesson, snippet_before, snippet_after, provenance, created_at, condition)` — no profile data, no full kernel source. `condition` is a deterministic applicability signature (run bottleneck + sorted action params, e.g. `"compute_bound | BLOCK_N=32"`; run-scope rows carry bottleneck only); it's part of the dedup key and is rendered to the Planner as `"applies when: …"`. `MemoryStore` is **dedup-consolidated** JSONL at `opt_mem/store.jsonl` (single shared global path; tolerant load with schema-version skip + missing-field warns; `add` / `add_many` / `load` / `all`): `add`/`add_many` re-read disk + merge with in-memory + new rows via `dedup_best` (highest speedup per `(kernel, arch, scope, action, condition)`, ties → most recent `created_at`), then atomically rewrite the whole file (per-pid `tmp` + `fsync` + `os.replace`) — the disk re-read first means write-only mode (no prior `load()`) cannot truncate prior lessons; `load()` dedups in memory; forward-compat rows (`schema_version > KNOWN_VERSION` this binary can't parse) are carried through the rewrite verbatim so an older binary can't delete a newer binary's lessons. Single-writer assumption, no lock. `MemoryRetriever.sample(kernel_type, hardware_arch)` filters by kernel-type, hardware-preferred fallback, then iterative `random.choices` weighted by `speedup ** α` drawing WITHOUT replacement over a `dedup_best`-deduped pool (was `random.choices` with replacement) so no lesson row repeats in one prompt. `SummarizerAgent` wraps the shared `self._model` with two prompts (`summarize` = edge G1 / `summarize_run` = cumulative G3); all failure modes return `None` with a warn (never raises). `Producer` owns the per-run buffer + session-cap accounting (cap reserves 1 slot for G3; cap-1 edges contend with lowest-ratio eviction); `consider()` gates on write-enabled, compile/correct, `parent/child` ratio `>= δ`; `finalize()` writes one G3 row when cumulative ratio `>= δ`; both take a `bottleneck=` kwarg (threaded into `condition`); `flush()` read-merges + atomically rewrites the buffer at run end (no longer "appends"). Orchestrator classifies a once-per-run `run_bottleneck` and threads it into `consider()` / `finalize()`; calls `consider()` per iter after the child is dumped, then `_flush_opt_mem(root, tree, run_bottleneck)` before every `return SearchResult(...)` path. Opt-in via `opt_mem_write_enabled=True` (default off — ablations can't pollute the shared store). Read default on; `opt_mem_read_enabled=False` short-circuits to `[]`. Five config knobs live under `[memory]` in the `.cfg` and on `ACTSConfig`: `opt_mem_{read,write}_enabled`, `opt_mem_writes_per_session_cap=20`, `opt_mem_min_improvement_ratio=1.05` (δ), `opt_mem_speedup_weight_alpha=1.0` (α), `opt_mem_store_path=opt_mem/store.jsonl`. `opt_mem/` `.gitignored`. Tier 1 tests: `test_memory_{experience,store,retriever,summarizer,producer}.py` + `test_orchestrator_opt_mem_integration.py`, all mocked. Pure Python; no GPU code paths. Replaces the v1 schema (`metrics` / `reviewer_summary` / `bottleneck_before` / `success` / `hardware`) and the v1 `retrieve()` API wholesale — no production data to migrate, no deprecation cycle. Spec: `doc/specs/2026-05-24-optimization-memory-design.md`.

### Correctness-subprocess isolation (landed 2026-05-31)
Closes the last in-parent untrusted-kernel-launch site, completing the subprocess-isolation arc Scope B+ (bench + NCU) started. Same poison *class* (`cudaErrorIllegalAddress` / device-side-assert sticky-context), different *site*: after Scope B+ moved bench + profile into the per-iter child, correctness verification was the only remaining place an LLM-authored kernel launched in the long-lived parent. Trigger run `runs/run_20260529T142421_439323Z` produced zero improvement across the whole run — one out-of-bounds candidate in the in-parent correctness check fired a device-side assert that poisoned the parent context, and three fail-open input-generator sites swallowed the resulting sticky errors *silently* so the run kept "advancing" through iters that could no longer produce a working candidate. Design rationale: JOURNAL → "Correctness-subprocess isolation — closing the last in-parent untrusted-launch site (2026-05-31)".
- **src/eval/worker_spawn.py** — new shared parent-side spawn skeleton. `spawn_worker(...)` owns the `subprocess.Popen` + `asyncio.to_thread(proc.wait, timeout)` watchdog + terminate/sleep(2)/kill escalation + crash-classification dance that bench and correctness both need; returns a structured `WorkerOutcome` (`"ok"` / `"timeout"` / `"crashed"`) with byte-for-byte-preserved (returncode, log_tail) payloads. `bench_subprocess.run_bench_subprocess` is refactored onto it (one implementation, two callers).
- **src/eval/correctness_worker.py** — new child-process entrypoint (`python -m src.eval.correctness_worker --request r --response w`). Rebuilds the candidate from the request, compiles, and verifies it against the PyTorch oracle IN-CHILD so an OOB launch dies with the child. Two modes: `"gate"` (the 5-stage `verify_correctness` per workload — the Coder tool) and `"strict_recheck"` (anti-cheat + strict-tolerance compare per workload — the orchestrator reward-hack re-eval). Reuses bench_worker's rehydration helpers; torch/SOL imported lazily so the module stays importable under the Tier-1 torchless venv.
- **src/eval/correctness_subprocess.py** — new async parent-side helper (mirrors `bench_subprocess`). `run_correctness_subprocess(...)` writes `request.json`, spawns the worker, awaits exit, parses `response.json`; any failure (non-zero exit, signal, missing/malformed response, timeout) becomes a **fail-closed** `CorrectnessResult(passed=False)` — the parent is never poisoned because the launch happened in the now-dead child. `CorrectnessIsolationError` is the trust-gate tripwire (below).
- **Three parent-side launch sites isolated** — the Coder's `check_correctness` tool (now `async`, `src/agents/coder.py`), the orchestrator's reward-hack re-eval (`_reward_hack_re_eval`, `mode="strict_recheck"`, `src/search/orchestrator.py`), and the baseline post-verify (`src/benchmark/baseline_generator.py`).
- **Trust gate by construction** — `allow_in_parent_fallback=False` (default) makes "no untrusted launch in the parent" enforced at the call boundary: a path that forgets to thread `problem_definition_path` now raises `CorrectnessIsolationError` loudly instead of silently falling back to an in-parent launch (the exact hole this PR closes). The opt-in in-parent compare (`strict_compare_one_workload` per workload inside a fresh `per_iter_anti_cheat`) is reachable only for trusted/mocked contexts that pass `allow_in_parent_fallback=True`.
- **src/config.py** — `correctness_worker_timeout_s: float = 180.0`. Deliberately NOT the bench `worker_timeout_s` (~50h, sized for NCU profiling): a hung correctness candidate under that ceiling would stall the run for ~2 days. Correctness is a fast check; 180s bounds the hang.
- **src/eval/correctness.py** — `strict_compare_one_workload` factored out (shared by the worker's strict_recheck mode and the in-parent fallback); `build_correctness_request` factors request-construction out of the worker. The three fail-open input-generator sites now **swallow-LOG** (sticky error recorded, not silently eaten) so a future poison surfaces in the logs; `del _repr_inputs` after the dtype-probe frees probe VRAM; correctness scratch dirs are cleaned up after each call.

NOT isolated now because the compile tool fires per self-check (high frequency) — bad cost ratio against a low residual. *Revisit → full compile-tool subprocess isolation ONLY if* a host-wrapper poison OR hang is observed in a real run.

### Optimization-memory condition-keyed dedup (landed 2026-06-02)
Supersedes the append-only `MemoryStore` design (RESOLVED 2026-05-28 entry below) with a **dedup-consolidated** store: lessons collapse on a condition-aware identity key so the same technique under the same applicability signature stores once (highest speedup wins), while distinct conditions stay separate. Closes the unbounded-growth + duplicate-lesson failure mode the append-only store left open, and gives the Planner an "applies when: …" applicability hint per lesson.
- **src/memory/experience.py** — `Experience` gains a `condition: str = ""` field — a deterministic applicability signature (`"<bottleneck> | k=v, k=v"` from run bottleneck + sorted action params; run-scope rows carry bottleneck only). `_format_condition(bottleneck, action)` builds it; `dedup_key(exp)` keys on `(kernel_type, hardware_arch, scope, action_id, condition)` (run-scope rows use the `"∅"` action sentinel); `dedup_best(rows)` collapses each key to the highest-speedup row (ties → most recent `created_at`), preserving first-seen key order.
- **src/memory/store.py** — `MemoryStore` is no longer append-only: `add`/`add_many` re-read disk + merge with in-memory + new rows via `dedup_best`, then atomically rewrite the whole file (per-pid `tmp` + `flush` + `fsync` + `os.replace`); the disk re-read first means write-only mode (no prior `load()`) cannot truncate prior lessons. `load()` dedups in memory. `_parse` returns `(experiences, passthrough_future_raw_lines)` — forward-compat rows (`schema_version > KNOWN_VERSION` this binary can't parse) ride through the rewrite verbatim so an older binary can't delete a newer binary's lessons. Tolerant guards (malformed-JSON skip, non-dict skip, schema_version coerce/skip, missing-field warn-once, speedup guard, title/lesson type-guard, non-string identity-field skip, non-string `condition` drop-to-`""`-keep-row) shared by load + write path. Single-writer assumption, no lock. Legacy rows (no `condition` key) backfill a params-only condition so edge rows differing only in params keep distinct keys on migration.
- **src/memory/retriever.py** — `MemoryRetriever.sample(...)` deduplicates the candidate pool via `dedup_best` before sampling, and `_weighted_sample` draws WITHOUT replacement (iterative `random.choices` re-weighting `speedup ** α`) so no lesson row repeats in one prompt (was `random.choices` WITH replacement).
- **src/memory/producer.py** — `consider(..., bottleneck=None)` + `finalize(..., bottleneck=None)` take the run bottleneck and thread it into `_format_condition`; `flush()` calls `add_many` (read-merge + atomic rewrite, no longer "append").
- **src/search/orchestrator.py** — threads the once-per-run `run_bottleneck` (from `classify_run`) into `consider()` / `finalize()` and `_flush_opt_mem(root, tree, run_bottleneck)` at every return path.
- **src/agents/planner.py** — renders each retrieved lesson's `condition` as `", applies when: <safe_cond>"` (via `_neutralize_metadata` single-line flattening).
- **Reviews** — two Codex review rounds + a `simplify` pass landed during the feature.
- **Tests** — `tests/test_memory_{experience,store,retriever,producer}.py` + `tests/test_planner.py` updated/extended for the condition field, `dedup_best`/`dedup_key`, atomic-rewrite + forward-compat passthrough, without-replacement sampling, and `applies when:` rendering; 128 unit tests green. Pure Python; no GPU code paths.

## Framework Enhancement Investigation — "Baseline Always Wins" (2026-05-13)

Observed symptom: across trial ACTS runs, the best-performing kernel found by the search is always the Triton baseline (root). Five-way parallel recon across AccelOpt, Astra, autokernel, evotoolkit, and `knowledge-data-base/wiki/kernel-agent` produced a ranked roadmap of techniques ACTS lacks. Each item is a recommendation pending its own brainstorm/plan round — nothing here is decided, nothing has landed.

**Diagnosis — three root causes (multi-recon consensus)**:

1. **Triton baseline is autotuned; ACTS candidates aren't.** Every system that reports beating strong baselines (AVO vs cuDNN, EvoEngineer 2.72×, KernelEvolve 100% pass on KernelBench) wins on the parameter-search axis (BLOCK / num_warps / num_stages). ACTS's tier-1 actions name `block_size_tuning` but Planner picks one value per iter — a single config vs the baseline's autotuned envelope.

2. **One candidate per plan = single noisy draw.** AccelOpt's loop runs `breadth=4 × num_samples=2 = 16 candidates/iter` and keeps the best per plan (`scripts/executor.py:112-119`). ACTS runs `1 plan × 1 candidate`. If the Coder's median draft regresses (typical on already-decent Triton), ACTS loses every iteration. Best-of-K converts the question from "median vs baseline" to "best-of-K vs baseline." (Note: the existing "Parallel kernel candidate generation" Post-V1 line below is the same idea — this investigation promotes it from speculative-future to symptom-driven.)

3. **Thin per-iteration signal feeding the Planner.** ACTS Planner sees Reviewer prose, the action library, and the parent kernel source verbatim. The actual signal gaps: **NO per-shape deltas** (Astra's `format.py:244-291` shows the strategist per-shape time/throughput differences), and **NO categorical bottleneck routing** (autokernel's `bench.py:1071-1083` emits `memory_bound|compute_bound` directly into tier-choice instead of routing through Reviewer prose). Without these structured signals the Planner re-suggests techniques the parent already applied. **Note**: A3's refined scope (autotune-block condensation, landed 2026-05-14) addresses a secondary signal-quality issue — A1's mandatory autotune block crowds the rendered source — not the source-visibility issue this root cause originally claimed.

Two amplifying absences: no recombination (every child has exactly one parent — siblings can't merge their fixes) and fixed `T_b` (SOL Score's anchor never ratchets — Planner stays oriented to the original kernel forever).

  - **`asyncio.to_thread(proc.wait)` cancellation can't interrupt the subprocess** (`bench_subprocess.py:run_bench_subprocess`). The blocking `proc.wait()` runs in a worker thread; asyncio cancellation (operator Ctrl-C during a 1800s `worker_timeout_s` wait, or sibling-coroutine cancel) raises `CancelledError` in the coroutine but the thread + child + GPU lock keep running until external SIGKILL. *Trigger*: operator interrupts a long-running optimize and the GPU stays held by an orphan child after the parent appears to exit; clock-lock leak on top. *Fix shape*: install an asyncio task-cancel handler that explicitly `proc.terminate()` + `proc.kill()` before re-raising `CancelledError`; OR use `asyncio.create_subprocess_exec` with a managed `await proc.wait()` so cancellation propagates natively (bigger refactor).

  - **Non-atomic `response.json` write in `_main_cli`** (`bench_worker.py`). `args.response.write_text(json.dumps(response))` is a single non-atomic call; SIGKILL/OOM-kill mid-write leaves a truncated file. Codex 2026-05-26 fix #2 catches the resulting `JSONDecodeError` as `WorkerCrashed` on the parent side, so the symptom is contained — but the corruption itself is preventable. *Trigger*: postmortem analysis where a `bench_worker_crashed` event's `stderr_tail` shows no real worker error (the worker logic completed; only the write was interrupted), wasting a crash-counter increment on a clean condition. *Fix shape*: write to `response.json.tmp` then `os.replace(...)` — POSIX-atomic appearance of the final file.

  - **`request["ncu_cache_dir"]` is written by parent but never read by child** (`bench_worker.py:_run_profile_gauntlet` passes `cache_dir=worker_dir` instead of the request's shared cache dir). The shared NCU JSON cache (keyed by source-hash) is therefore never populated/hit across iters; every profile call respawns the NCU subprocess (~tens of seconds). Meanwhile `merge_worker_artifacts` copies `cand_<idx>.ncu-rep` into the shared cache with non-hash filenames, polluting it with files the hash-keyed lookup will never reuse. *Trigger* (any): live run where the same kernel source recurs (re-eval after `reward_hack_cleared`, K-way duplicates from low-temperature decoding, plateau retries) and NCU wallclock dominates; postmortem showing identical NCU work repeated. *Fix shape*: child reads `request["ncu_cache_dir"]` and passes it as `profile_kernel(cache_dir=ncu_cache_dir)`; the rename step still lands `.ncu-rep` under `worker_dir/cand_<idx>.ncu-rep` (for postmortem + tree_dump), separately from the source-hash-keyed cache (for cross-iter hits).

  - **Profile gauntlet uses fake `lambda seed: ()` input generator when workloads is empty** (`bench_worker.py:_run_profile_gauntlet`). When `workloads=[]` but somehow a candidate reaches the gauntlet (placeholder smoke + non-empty cands path; today this combo is gated upstream but the worker still has the lambda fallback), `profile_kernel` calls the fake generator and the NCU subprocess crashes calling the kernel with zero arguments.   - **`coder_submitted.n_profile_attempts` hardcoded to 1** (`orchestrator.py`). The OLD profile-gauntlet emitted `n_profile_attempts` as the 1-indexed rank of the profile-success winner (per `events.py` docstring: `>1 means profile-fallback engaged`). The worker now runs the gauntlet but doesn't report the attempt count; parent records `profile_attempts = 1` as a placeholder. *Trigger* (any): postmortem where profile-fallback rate matters for sweep analytics; ≥3 live runs where a SOL-ranked top candidate hits `ProfilerError` and a lower-ranked sibling wins (which would have shown `n_profile_attempts > 1` pre-refactor). *Fix shape*: worker's `_run_profile_gauntlet` returns `(winner_idx, winner_profile_dict, profile_attempts)`; parent threads it into `emit("coder_submitted", ..., n_profile_attempts=response["profile_attempts"])`.

  - **`_emit` uses locale-default text encoding** (`bench_worker.py`). `(worker_dir / "events.jsonl").open("a")` — no `encoding=` — uses Python's locale default. On non-UTF-8 hosts (containers with `LANG=C`, Windows defaults) a non-ASCII char in any event field (em-dash in a traceback, unicode in a kernel name) raises `UnicodeEncodeError` which the `except: pass` swallows. Events silently disappear from the chunk; downstream sees gaps in the timeline with no logged warning. *Trigger* (any): ACTS deployed in a non-UTF-8 container; postmortem with unexplained missing events on a run that included unicode source. *Fix shape*: `open("a", encoding="utf-8")` — one-line.

After the bench-dispatch refactor, `agent_failure_count` is bumped inside the per-cand response loop but never read post-dispatch; the variable's used in the all-Coder-failed gate that fires BEFORE bench dispatch. The bump has no effect on parent quarantine — that's correctly handled by `parent.consecutive_agent_failures += 1` in the channel-A iter-level abort branch. *Trigger*: code-reading time-sink only — not a runtime bug. *Fix shape*: delete the bump, or repurpose if a future post-dispatch consumer needs it.

  - **Entrypoint-binding pre-filter never emits `coder_failed`** (`orchestrator.py` pre-filter branch). When `find_jit_name_in_entrypoint` returns False on a candidate, the parent silently persists the failure via `_accumulate_iter_failure` — but the helper only emits `coder_failed` for worker-reported statuses (the pre-filter path predates this code shape). Matches OLD behavior (which also silent-persisted), so no regression — but downstream consumers that tally `coder_failed` events under-report entrypoint-binding failures. *Trigger*: postmortem where the failure-summary tree-node count doesn't match the `coder_failed` event count; sweep analytics that aggregate by event count miss the entrypoint-binding class. *Fix shape*: emit `coder_failed{reason="EntrypointBinding: ..."}` at the pre-filter accumulate site.

  - **`_rehydrate_hardware_spec` constructs zero-HardwareSpec on malformed dict** (`bench_worker.py`). The helper filters incoming dict to known fields and constructs via `HardwareSpec(**kwargs)`; `HardwareSpec` has 17 fields all defaulted, so a malformed/empty dict silently yields all zeros. The parent's pre-flight zero-peak fail-fast check (`orchestrator.py:733`) is parent-only — not mirrored at the child request boundary. `profile_kernel` then divides by zero peaks → `ProfilerError` per candidate → every candidate dropped → `winner_idx=None` every iter.   - **`_read_tail` reads entire `worker.log` into memory before slicing** (`bench_subprocess.py`). `data = path.read_bytes()` then `data[-max_bytes:]` — works fine for normal log sizes but pathological growth (a worker that prints heavily for the full 1800s timeout, NCU `--verbose` accidentally enabled, kernel crashing in a tight retry loop) can balloon `worker.log` to hundreds of MB.   - **Zombie process from `proc.kill()` without `proc.wait()`** (`bench_subprocess.py:run_bench_subprocess`). After watchdog timeout, helper calls `proc.terminate()` + sleep + `proc.kill()` but never `proc.wait()` to reap. On Linux the child stays as `<defunct>` until parent exits. Compounded with high `worker_crash_threshold` and a stuck worker pattern, accumulates multiple zombies. Also: `proc.poll()` vs `proc.kill()` race — kill can `ProcessLookupError` if the child exited between poll and kill, escaping `WorkerCrashed` assembly. *Trigger* (any): long-running operator session with repeated watchdog timeouts (workers stuck in CUDA D-state, kernel deadlock); `ps -ef | grep defunct` shows accumulating zombies under the parent PID. *Fix shape*: add `try: proc.wait(timeout=5) except: pass` after kill; wrap `proc.kill()` in `try/except ProcessLookupError`.
