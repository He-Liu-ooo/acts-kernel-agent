### Evaluation Harness
- **eval/correctness.py** — 5-stage gate (smoke → shape-sweep → numerical stability → determinism → anti-cheat) with short-circuit failure attribution. Injectable `ComparisonPolicy` (torch-free at import); `TorchComparisonPolicy` delegates to `sol_execbench.compute_error_stats` and fails closed without SOL. Workload-carried `ToleranceSpec` overrides every stage's atol/rtol — including stage 5's strict tolerances — so anti-cheat matches the per-problem spec (opt-in via `workload` presence).
- **eval/inputs.py** — `build_reference_fn` (exec PyTorch reference, resolve `run`) + `build_input_generator` (wraps SOL's `gen_inputs` with seeding) + `allocate_dps_outputs` (Tier 6). Safetensors entries detected at build time and pre-loaded once via `load_safetensors` (Tier 7) so on-disk reads stay out of the per-iteration timing path.
- **eval/benchmark.py** — CUDA-event timing via injectable `BenchmarkTimer` Protocol. Production `_TorchCudaTimer` uses `torch.cuda.Event` pairs + 256MB int64 L2 thrasher. Multi-workload parallel-list contract with fresh-timer-per-workload isolation; fail-closed on partial-workload failures (<half survive → `BenchmarkError`); 100us sentinel on empty-workload path; `is_fully_successful` for orchestrator gating. A1 PR 1/B: one autotune burn-in call fires before warmup at reserved seed `_BURN_IN_SEED = -1` so Triton's autotune compile + config sweep stays outside the timed window. `benchmark_kernel(..., autotuner=...)` snapshots `autotuner.cache` around each workload and records `BenchmarkResult.autotune_winner_per_workload` from single-entry cache deltas. `benchmark_kernel` clears `autotuner.cache` at entry to keep per-workload cache-delta winner attribution correct after the Coder's correctness pass (the correctness pass compiles + launches the kernel before bench, so Triton's `@triton.autotune` may have already cached winners for our workload shapes); flips `autotuner_usable=False` defensively on `AttributeError`.
- **eval/profiler.py** — hybrid analytical roofline (optional, degrades to NCU-only on missing byte counts) + curated NCU subprocess (best-effort, degrades on failure). Curated NCU subset = REQUIRED {`sm_occupancy_pct`, `l2_hit_rate_pct`} + OPTIONAL {`tensor_core_util_pct: float | None`}; absence of an OPTIONAL metric yields None rather than degrading the whole profile (e.g. Ada elementwise kernels emit no tensor-core counter; discarding occupancy + L2 + stalls because one diagnostic is missing was a regression of the "degrade gracefully" contract). `ProfilingResult.analytical: AnalyticalMetrics | None` with `has_analytical` property; `profile_kernel(nbytes=0)` skips the analytical block, NCU still runs. Source-hash-keyed cache stores both the curated `NCUMetrics` and the full `raw_metrics` dict; cache hits rehydrate both so `Reviewer.query_metric` works the same on re-profile as on the originating iteration. Per-iter signals feed Reviewer; run-level classification via `classify_run`.
- **eval/roofline.py** — two clean paths: SOLAR (`derive_t_sol_from_solar`, `source="solar"`) or built-in `compute_roofline()` fallback (`source="builtin"`). `RooflineResult.bottleneck` typed as `BottleneckType` enum end-to-end. `RooflineResult.total_flops` / `total_fused_bytes` carry SOLAR's absolute counts through to downstream consumers.
- **benchmark/roofline_shapes.py** — `compute_roofline_inputs(definition, workload, *, roofline=None)` accepts an optional `RooflineResult`; when SOLAR-derived `total_flops` / `total_fused_bytes` are both > 0 they outrank the shape formulas, and the function returns `(0, nbytes)` when only flops can't be derived (view/mask-heavy kernels) so analytical degrades cleanly to memory-only or NCU-only rather than failing closed.
- **eval/scorer.py** — SOL Score formula + `reward_hack_suspect` / `calibration_warning` audit flags (SOL-ExecBench paper §4.3).
- **eval/anti_cheat.py** — three surfaces: correctness-level (Stage 5 in `eval/correctness.py`), performance-level (scorer audit flags), process-level (`per_iter_anti_cheat` context manager + `check_lazy_outputs_after_bench` wired to SOL's `reward_hack` detector set). Active clock-lock end-to-end on RTX 6000 Ada.

## Framework Enhancement Investigation — "Baseline Always Wins" (2026-05-13)

Observed symptom: across trial ACTS runs, the best-performing kernel found by the search is always the Triton baseline (root). Five-way parallel recon across AccelOpt, Astra, autokernel, evotoolkit, and `knowledge-data-base/wiki/kernel-agent` produced a ranked roadmap of techniques ACTS lacks. Each item is a recommendation pending its own brainstorm/plan round — nothing here is decided, nothing has landed.

**Diagnosis — three root causes (multi-recon consensus)**:

1. **Triton baseline is autotuned; ACTS candidates aren't.** Every system that reports beating strong baselines (AVO vs cuDNN, EvoEngineer 2.72×, KernelEvolve 100% pass on KernelBench) wins on the parameter-search axis (BLOCK / num_warps / num_stages). ACTS's tier-1 actions name `block_size_tuning` but Planner picks one value per iter — a single config vs the baseline's autotuned envelope.

2. **One candidate per plan = single noisy draw.** AccelOpt's loop runs `breadth=4 × num_samples=2 = 16 candidates/iter` and keeps the best per plan (`scripts/executor.py:112-119`). ACTS runs `1 plan × 1 candidate`. If the Coder's median draft regresses (typical on already-decent Triton), ACTS loses every iteration. Best-of-K converts the question from "median vs baseline" to "best-of-K vs baseline." (Note: the existing "Parallel kernel candidate generation" Post-V1 line below is the same idea — this investigation promotes it from speculative-future to symptom-driven.)

3. **Thin per-iteration signal feeding the Planner.** ACTS Planner sees Reviewer prose, the action library, and the parent kernel source verbatim. The actual signal gaps: **NO per-shape deltas** (Astra's `format.py:244-291` shows the strategist per-shape time/throughput differences), and **NO categorical bottleneck routing** (autokernel's `bench.py:1071-1083` emits `memory_bound|compute_bound` directly into tier-choice instead of routing through Reviewer prose). Without these structured signals the Planner re-suggests techniques the parent already applied. **Note**: A3's refined scope (autotune-block condensation, landed 2026-05-14) addresses a secondary signal-quality issue — A1's mandatory autotune block crowds the rendered source — not the source-visibility issue this root cause originally claimed.

Two amplifying absences: no recombination (every child has exactly one parent — siblings can't merge their fixes) and fixed `T_b` (SOL Score's anchor never ratchets — Planner stays oriented to the original kernel forever).
